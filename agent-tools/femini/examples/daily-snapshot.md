# 案例：一个 Click URL 的日度快照

可复验任务模板；`<LEGACY_ID>` 是占位符，不是真实客户数据。优先使用任务给定的 legacy Click URL；若未给定，按[指南](../README.md)通过本人有权访问的产品对象列表或现有原生只读实体工具，结合任务客户范围筛选并核实归属。无客户范围、无权限或无法确认归属时停止并说明缺项，不擅选无关客户，也不假定历史样本对所有人可用。日期指定 2026-11-03 单日。执行前阅读[指南](../README.md)并检查当前工具 schema。

1. 未完成本人授权原生接入时停止原生调用；网页只可核对可见字段，不能作为原生调用验收，也不提取安装页令牌或再次索要被拒绝的凭据。发现原生工具后，核实当前身份；读取实体查询和 `get_click_url_spend_metrics` schema。确认 `<LEGACY_ID>` 是字符串形式的 Click URL legacy ID 及其归属。不可确认就停止。
2. 按 schema 调用 `get_click_url_spend_metrics`：`click_url_name=<LEGACY_ID>`、`start_date=2026-11-03`、`end_date=2026-11-03`。工具不可用或拒绝访问时记录具体错误，不用别的身份。
3. 逐日列日期、记录 Spend、已选事件与已导入 Partner Cost，注明每列来源、单位、`null` 与 `0`、覆盖范围和刷新时间；未返回的单位或时间写未知。对照原始输出及有权限的页面。
4. 先按指南查看已确认的 Click URL 详情、Spend Request、定价与事件来源等只读资料，核对方法、费率、生效日期和路由；仅在这些条件与实际 schema 均已核实时，可执行只读 `preview_campaign_spend`；记录方法、费率、来源、现值、拟算值、逐行状态和 warning。缺失任何条件就停止试算、列明缺项并标记“试算待验证”，不猜参数或结果。若需月度结论，单独检查月度调整。
5. 将原始输出放私有受控位置；不要保存或提交会话凭据、密钥或客户数据。输出可复验范围和证据、失败及未查明项。
