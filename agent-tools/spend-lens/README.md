# Spend Lens：已录入 Spend 检查

## 入口与前提

打开 https://spend-lens.feedmob.com，使用操作者本人获授权的 FeedMob Google 账号，从实际首页进入新对话。需要可操作该网页的浏览器；没有浏览器能力的 Agent 不能直接调用产品内部工具，也不能假定有外部 MCP/API。2026-11-14 Kaz 在 Browser 标签页登录成功并创建私有检查会话；成功进入不证明检查结果或其他用户权限。

适合检查 Admin L1 `net_spends` 的异常和可证实原因；不做 Client Report 对比，也不覆盖 L0/L2。源码所述单次最多 31 天，手动最多 50 个 Click URL；以实际页面和服务响应为准，日期采用 UTC Spend Day。历史配置可能不完整，`link_type` 据源码使用当前值。

## 步骤

1. 优先使用任务指定的 legacy Click URL；若未给定，先在本人有权访问的产品对象列表或现有原生只读实体工具中，按任务指定的客户范围筛选并核实归属和访问权限。不得擅选无关客户，也不能假定样本 23567 对所有人可用。若缺少客户范围或无法确认归属，停止并写明缺项；同时核实日期。不要提交不必要的客户明细。
2. 在新对话提交明确要求：逐日检查指定范围的 Admin `net_spends`、异常、外部源状态和有证据的原因；要求缺失与未知明确标示。明确禁止创建外部报表、上传或修改数据。若界面显示需要这些额外业务副作用，停在该步骤并记录，勿继续。
3. 检查完成状态及底层证据：范围、记录数、逐日金额和单位、异常类型、来源、来源状态（complete / unavailable / denied / delayed / unsupported 等）、证据链接及已知限制。报告中源不可用或缺失不等于零；未能识别原因标记未查明。展开会话中类似 “Worked for… · N steps” 的步骤区，逐条展开并加载底层工具结果，核对原始来源与模型回答；界面以实际显示为准，不固定步骤编号。如果步骤无法打开或加载，记录未复核，不能当作底层证据已核实。不能自行推算未经工具支持的金额。
4. 若尚在运行、失败、无数据或访问被拒，分别保留状态与时间；不得当成无异常。保存操作者可访问的私有对话链接，不开启 Share，也不把业务内容提交仓库。可追问但保持本期只读、无额外报表副作用。
5. 按业务需要转至 Femini 做独立快照或试算，先核对 ID、日期和口径；不假设系统同步或必须串联。

## 常见故障

登录失败或账户被停用：本人通过正常渠道处理；不能换别人的账号。源 denied/unavailable：记录源和实际错误；delayed：记录仍未完成，不能称为成功。缺失日期或记录不自动代表零消耗、漏录或根因。检查可能触发异步外部报告，出现此类行为或要求时停止，除非另获明确授权。
